# Custom canvas overlay broke rendering — revert to L.canvas() renderer

**Date:** 2026-02-17 01:00
**Files:** src/gui/map_widget.py
**Severity:** critical

## Problem

After replacing Leaflet-native polylines with a custom `<canvas>` overlay
for track line and active waypoint line:
1. Track line disappeared completely
2. Active waypoint line disappeared
3. Lags persisted (actually worsened during pan)

## Root Cause

The custom `_hpCanvas` was `position: absolute` in the map container,
NOT inside the Leaflet map pane. During pan, Leaflet moves the map pane
via CSS transform (GPU, zero JS). Our canvas was outside this pane, so
it had to REDRAW all 1000 track points on every `move` event (~60fps
during pan). This is WORSE than the original problem.

Additionally:
- `_hpResize` IIFE added duplicate `map.on('resize')` listeners on
  every resize call (memory leak)
- Canvas may have had 0 dimensions on init (IIFE runs before container
  has layout)
- World-pixel projection + offset calculation had precision issues

## Solution

Reverted to Leaflet-native `L.polyline` objects with a **shared
`L.canvas()` renderer** (`_dynRenderer`). Key insight:

- `L.canvas()` renderer lives INSIDE the map pane
- During pan, it moves via CSS transform (GPU, zero JS redraw)
- Only redraws on actual data change (setLatLngs) or zoom
- Route segment lines stay on default SVG renderer (separate DOM)
- Track and waypoint line are isolated on their own Canvas renderer

Throttling preserved:
- `trackLine.setLatLngs()` every 3rd frame (~3Hz)
- `activeWaypointLine.setLatLngs()` every 5th frame (~2Hz)

## Prevention

- NEVER create custom canvas overlays outside the Leaflet pane system
- Leaflet's renderers (L.canvas, L.svg) are inside panes and get free
  CSS transform during pan — always use them
- If custom rendering is needed, extend L.GridLayer (tiles move via CSS
  transform) or L.Canvas (inside pane)
- Test rendering BEFORE committing — visual regression is easy to catch
